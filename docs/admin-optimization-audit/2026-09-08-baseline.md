# Admin data optimization baseline

- Date: 2026-09-08
- Git baseline: `pre-admin-data-optimization-20260908`.
- No analytics, inquiry, customer, content, or media records will be deleted by this change.
- Customer attribution will only merge visitor histories after a matching submitted email or phone number; IP addresses remain masked and are not used as an automatic identity key.

## Implemented scope

- Standard date controls now use Today, This Week, This Month, and Custom Range in the Asia/Shanghai timezone.
- Analytics, visitor, customer, journey, inquiry, content, audit, sync, and Search Console reporting surfaces use the shared date model where their records have real timestamps.
- Catalog and static UI-asset records are intentionally not assigned fabricated dates.
- Every expanded operational list uses 25, 50, or 100 rows per page. News uses the same bounded client-side editorial table controls.
- Customer profiles aggregate only visitor IDs that were linked by a matching submitted email or phone number. Anonymous visitors remain separate until an inquiry provides a verified contact field.
- Traffic reports continue to include only `traffic_status = real`; excluded and review events remain available in the data-quality audit rather than being deleted.

## Rollback

- Restore the application to the annotated `pre-admin-data-optimization-20260908` tag, or revert the optimization commit after it is created.
- This change does not delete or mutate analytics events, inquiries, Blog articles, News records, products, media, or admin users.
